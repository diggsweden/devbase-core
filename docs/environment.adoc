= Environment Variables

== Overview

This document covers:

- **A) Variables that persist AFTER installation** in your shell environment
- **B) Variables for non-interactive installation** (CI/automation)

For interactive installation, the installer prompts for required values (Git, theme, editor).

Defaults are defined in `config/defaults.env` and referenced throughout the installer.

== A) Post-Installation Variables (Persistent)

These are exported in your Fish shell after installation:

[cols="2,2,3", options="header"]
|===
| Variable | Default | Description

| `BAT_THEME`
| _(theme-based)_
| Syntax highlighter theme for `bat`

| `DEVBASE_THEME`
| `everforest-dark`
| Current theme

| `DEVBASE_ZELLIJ_AUTOSTART`
| `false`
| Auto-start Zellij terminal multiplexer

| `EDITOR`
| `nvim`
| Default text editor

| `FZF_DEFAULT_OPTS`
| _(theme-based)_
| Fuzzy finder colors for `fzf`

| `VISUAL`
| `nvim`
| Visual editor (same as EDITOR)
|===

=== Modifying After Installation

Edit `~/.config/fish/conf.d/10-personal.fish`:

[source,fish]
----
# Switch to light theme (use devbase-theme command instead)
devbase-theme everforest-light

# Enable Zellij autostart
set -gx DEVBASE_ZELLIJ_AUTOSTART "true"

# Change editor
set -gx EDITOR "nvim"
set -gx VISUAL "nvim"
----

== B) Non-Interactive Installation Variables

For CI/automation, set these with `./setup.sh --non-interactive`:

[cols="2,2,3", options="header"]
|===
| Variable | Default | Description

| `DEVBASE_THEME`
| `everforest-dark`
| Theme: `everforest-dark`, `everforest-light`, `catppuccin-mocha`, `catppuccin-latte`, `tokyonight-night`, `tokyonight-day`, `gruvbox-dark`, `gruvbox-light`, `nord`, `dracula`, `solarized-dark`, or `solarized-light` (authoritative list in `libs/theme-registry.sh`)

| `EDITOR`
| `nvim`
| Default editor: `nano` or `nvim`

| `GIT_EMAIL`
| `$USER@$(hostname)`
| Git user.email (e.g., "jane@example.com")

| `GIT_NAME`
| `DevBase User`
| Git user.name (e.g., "Jane Doe")

| `DEVBASE_SSH_KEY_ACTION`
| `keep` if a key exists, else `new`
| Set to `new` to replace an existing key; the old one is renamed with a `.backup.<timestamp>` suffix

| `SSH_KEY_PASSPHRASE`
| _(auto-generated)_
| SSH key passphrase (displayed at end of installation if auto-generated)

| `DEBUG`
| _(unset)_
| Show verbose debug output during installation: `DEBUG=1 ./setup.sh`

| `DEVBASE_STRICT_CHECKSUMS`
| `warn`
| Checksum strictness: `off`, `warn`, or `fail`

| `DEVBASE_STRICT_CHECKSUMS_ALLOWLIST`
| _(unset)_
| Comma-separated URL patterns allowed without checksums

| `DEVBASE_MIN_WSL_VERSION`
| `2.7.7`
| Minimum WSL version accepted when installing under WSL

| `DEVBASE_MIN_UBUNTU_VERSION`
| `26.04`
| Minimum Ubuntu release the update path will install onto

| `DEVBASE_NPM_MIN_RELEASE_AGE`
| `7`
| Days an npm package must be published before it may be installed

| `DEVBASE_CORE_REF`
| _(latest tag)_
| Branch or tag the persisted core repo tracks, for testing a branch or pull request (same as `./setup.sh --ref`, see link:development.adoc[Development Guide])

| `MISE_HTTP_TIMEOUT`
| `150s`
| Timeout for HTTP requests made by mise

| `MISE_FETCH_REMOTE_VERSIONS_TIMEOUT`
| `75s`
| Timeout for remote version lookups in mise
|===

NOTE: In non-interactive mode an SSH key is only generated when none exists, so re-running keeps the key you already have. If a key is generated and `SSH_KEY_PASSPHRASE` is not set, a secure random passphrase will be auto-generated. The passphrase will be displayed at the end of installation with instructions on how to change it. Make sure to save this passphrase before the installation summary disappears.

=== Example: CI/Automation

[source,bash]
----
export GIT_NAME="CI Bot"
export GIT_EMAIL="ci@example.com"
export DEVBASE_THEME="everforest-dark"
export EDITOR="nano"
./setup.sh --non-interactive
----

== Custom Config Variables (org.env)

Set in `devbase-custom-config/config/org.env` - affects installation behavior:

[cols="2,2,3", options="header"]
|===
| Variable | Default | Description

| `DEVBASE_EMAIL_DOMAIN`
| `@`
| Pre-fill email domain (e.g., `@company.com`)

| `DEVBASE_NO_PROXY_DOMAINS`
| `localhost,127.0.0.1`
| Domains to bypass proxy

| `DEVBASE_PROXY_HOST`
| _(none)_
| Organization proxy hostname

| `DEVBASE_PROXY_PORT`
| _(none)_
| Organization proxy port

| `DEVBASE_REGISTRY_HOST`
| _(none)_
| Internal package registry hostname

| `DEVBASE_REGISTRY_PORT`
| _(none)_
| Internal package registry port

| `DEVBASE_APT_REGISTRY`
| _(none)_
| Ubuntu archive mirror. Rewrites official archive/security URIs before APT update, preserving suites and signing keys. Original source files are saved under `DEVBASE_BACKUP_DIR/apt/`, following the standard backup rotation. Earlier adjacent `.devbase-backup` files are moved there automatically.

| `DEVBASE_GITHUB_REGISTRY`
| _(none)_
| GitHub release mirror with the same owner/repository paths. Used for installer downloads and checksums, including mise and Gum bootstrap.

| `DEVBASE_MISE_URL_REPLACEMENTS`
| _(none)_
| JSON map of upstream URL prefixes to mirrors. Exported as `MISE_URL_REPLACEMENTS` during bootstrap and persisted as global mise settings. Installation-statistics POSTs are disabled when configured.

| `DEVBASE_MISE_PYTHON_COMPILE`
| _(mise default)_
| Optional `true`/`false` setting for Python builds. Set `false` with a precompiled Python mirror to avoid the pyenv Git/source fallback. Applied during bootstrap and in global mise settings.

| `DEVBASE_RUSTUP_DIST_SERVER`, `DEVBASE_RUSTUP_UPDATE_ROOT`
| _(none)_
| Rust distribution and rustup update mirrors. Exported during installation and in Fish; when both are set, also supplied as the generated Rust tool's `install_env`.

| `DEVBASE_GO_REGISTRY`, `DEVBASE_GO_SUMDB`
| _(none)_
| Native `GOPROXY` and `GOSUMDB` values for installation and Fish. Keep the checksum database identity, e.g. `sum.golang.org https://registry.example/repository/gosum`.

| `DEVBASE_CARGO_REGISTRY`, `DEVBASE_RUBYGEMS_REGISTRY`
| _(none)_
| URLs used by optional custom `cargo-config.toml.template` and `bundle-config.template`. Seed native user config files without replacing existing files.

| `DEVBASE_EXTRA_FORGES`
| _(none)_
| Comma-separated list of extra code-forge hostnames to create under `~/development/` (e.g. `gitlab.mycompany.com,gitea.example.org`). The built-in forges (`gitlab.com`, `github.com`, `bitbucket.org`, `codeberg.org`, `code.europa.eu`) are always created.
|===

These inputs configure installation; supported client settings are also written to generated configuration or exported under their native names in Fish.

Registry integrations are opt-in independently: setting only `DEVBASE_REGISTRY_URL` does not redirect APT, mise or installer downloads. Without the specific settings, core retains its upstream behaviour. Put organization endpoints in `org.env`, not in core or project manifests.

When the mise map contains an HTTPS replacement for `https://api.github.com/`, setup does not prompt for a GitHub token. Upstream authentication belongs on that mirror. Other installations retain the existing optional-token check.

== Proxy Configuration

=== Runtime Proxy Handling

When DevBase detects proxy environment variables (`HTTP_PROXY`, `HTTPS_PROXY`, `http_proxy`, `https_proxy`), it automatically configures tools for better compatibility with corporate proxies:

==== Automatic Configuration

DevBase sets the following when a proxy is detected:

[cols="2,3", options="header"]
|===
| Configuration | Purpose

| `DEVBASE_CURL_PROXY_ARGS`
| Adds `--no-keepalive --no-sessionid -H "Connection: close"` for the internal curl wrapper

| `DEVBASE_WGET_PROXY_ARGS`
| Adds `--no-http-keep-alive` for the internal wget wrapper

| `devbase_curl` wrapper
| Uses configured proxy-safe curl options

| `NODE_USE_ENV_PROXY=1`
| Enables Node.js built-in clients to use `HTTP_PROXY`, `HTTPS_PROXY`, and `NO_PROXY` (including lowercase variants); preserves any explicit value
|===

Curl/wget compatibility settings are applied automatically:

- **During installation**: In `libs/handle-network.sh`
- **At runtime**: Via `~/.config/fish/functions/__devbase_configure_proxy_curl.fish` (loaded by Fish config)

Node's proxy default is applied during installation in `libs/bootstrap/bootstrap-apply.sh` and at Fish startup in `~/.config/fish/conf.d/06-node-config.fish`, after `00-proxy.fish`.
It is enabled when at least one HTTP or HTTPS proxy variable is nonempty, including inherited proxy settings.
It uses https://nodejs.org/docs/latest-v24.x/api/cli.html#node_use_env_proxy1[Node's documented environment-proxy support], available in DevBase's Node 24; libraries with custom agents may handle proxies separately.
To opt out, set `NODE_USE_ENV_PROXY=0` in the installation environment or add `set -gx NODE_USE_ENV_PROXY 0` to a personal Fish file such as `~/.config/fish/conf.d/50-personal.fish`.

==== Manual Testing

If experiencing proxy issues, test connectivity with:

[source,bash]
----
# Test all DevBase dependencies
./verify/verify-proxy-access.sh

# Test with forced no-keepalive mode
./verify/verify-proxy-access.sh --no-keepalive

# Test with actual downloads
./verify/verify-proxy-access.sh --download-test --no-keepalive
----
