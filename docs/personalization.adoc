= Personalization Guide

== Preserving Customizations

DevBase updates managed defaults and initializes personal configs only when absent. Paths below use the default XDG locations; create-only files are preserved even when empty or symlinked.

[cols="2,3",options="header"]
|===
|Configuration |Installation behavior

|SSH `~/.config/ssh/user.config` and `~/.ssh/known_hosts`
|Create-only. Known hosts are seeded from bundled and organization entries together; later host-key changes require manual verification.

|Maven `~/.m2/settings.xml`
|Create-only, from applicable proxy, registry or custom YAML fragments. No applicable configuration means no file is generated.

|Neovim `~/.config/nvim/`
|The entire existing path is preserved, including an empty directory or symlink. LazyVim initializes only an absent path when selected.

|Starship `~/.config/starship/starship.toml`, Testcontainers `~/.testcontainers.properties`, IntelliJ version-specific `idea64.vmoptions`
|Create-only personal defaults.

|Gradle `init.gradle` and `gradle.properties`; containers `~/.config/containers/registries.conf`
|Create-only when applicable. Gradle uses `GRADLE_USER_HOME`, defaulting to `~/.gradle`.

|Organization templates for personal paths, `.conf`, `.config` and `.service` files
|Initialize absent destinations only. See link:customization.adoc[Custom Configuration] for routes and managed-template overrides.

|Organization `bashrc.append`
|Appends the supplied block once, preserving existing content and permissions and keeping a backup. Linked `.bashrc` files are left for manual review.

|mise `~/.config/mise/config.toml`
|DevBase-managed global config, regenerated from package selections. Existing contents are backed up before replacement; use project configs for persistent project-specific selections.

|Fish `config.fish`, shipped `conf.d/` files and functions; `~/.config/git/config`; Zellij and other managed dotfiles
|Updated on reinstall. Personal files with noncolliding names survive; managed destination symlink conflicts stop the bulk copy, preserving the link and its target.
|===

For Fish customizations, use separate files such as `50-personal.fish` or `60-work.fish` whose names do not collide with shipped files. Numbering controls load order, not preservation: DevBase also ships `10-ulimits.fish`.

== Fish Shell

=== Default Aliases

DevBase provides these default aliases:

- `docker` → `podman` (container management)
- `vim`, `vi` → `nvim` (Neovim)
- `ls` → `eza --icons=auto` (better ls)
- `top` → `btop` (better top)
- `grep` → `grep --color=auto` (colored output)

=== Custom Aliases

[source,bash]
----
# Add to ~/.config/fish/conf.d/50-personal.fish
alias ll='ls -la'
alias dc='docker compose'
alias gs='git status'
----

=== Fish Abbreviations (Recommended)

Abbreviations expand in the command line and show in history (better than aliases):

[source,bash]
----
# Add abbreviations
abbr -a gco 'git checkout'
abbr -a gp 'git pull'
abbr -a dc 'docker compose'
abbr -a ll 'ls -la'

# List all abbreviations
abbr --show

# Remove an abbreviation
abbr -e gco
----

=== Custom Functions

[source,bash]
----
# Create function in ~/.config/fish/functions/gpr.fish
function gpr
    git pull --rebase $argv
end
----

== Git Configuration

Add personal Git settings in `~/.gitconfig`:

[source,bash]
----
git config --global alias.st status
git config --global alias.co checkout
git config --global pull.rebase true
----

Unrelated keys are retained, but setup explicitly configures selected identity, proxy, signing, certificate and hook settings with `git config --global`. The managed `~/.config/git/config` is also updated on reinstall.

== SSH Configuration

DevBase uses a layered SSH configuration system:

1. **User config** (`~/.config/ssh/user.config`) - Your personal hosts (included first, highest priority)
2. **Organization config** (`~/.config/ssh/custom.config`) - Organization-provided hosts
3. **Base defaults** (`~/.ssh/config`) - DevBase-managed settings after the includes

=== Adding Personal Hosts

Add to `~/.config/ssh/user.config`:

[source,ssh]
----
Host myserver
    HostName 192.168.1.100
    User myuser
    Port 2222

Host github-work
    HostName github.com
    User git
    IdentityFile ~/.ssh/id_ed25519_work
----

=== Overriding Organization Settings

SSH uses the first obtained value for most settings, so user config is loaded first:

[source,ssh]
----
# Organization provides (in custom.config):
Host github.com
  ProxyCommand nc -X connect -x proxy.company.com:8080 %h %p

# You override (in user.config):
Host github.com
  ProxyCommand none  # Direct connection without proxy
----

NOTE: DevBase creates `user.config` only when absent. Existing contents, empty files and symlinks are preserved across reinstalls.

`~/.ssh/known_hosts` is also initialized only when absent, combining `devbase_files/ssh/known_hosts` with organization `templates/known_hosts.append` and `ssh/known_hosts.append`. Existing files remain byte-for-byte unchanged, including empty files; symlinks are preserved. Verify later organization host-key changes through a trusted channel and update your file manually.

== Language/Locale Configuration

DevBase respects your system's existing locale by default. Organizations can configure their preferred locale through custom configuration.

=== Change System-Wide Locale

[source,bash]
----
# Change to English (US)
sudo update-locale LANG=en_US.UTF-8 LC_ALL=en_US.UTF-8

# Change to English (UK)  
sudo update-locale LANG=en_GB.UTF-8 LC_ALL=en_GB.UTF-8

# Change back to Swedish
sudo update-locale LANG=sv_SE.UTF-8 LC_ALL=sv_SE.UTF-8

# Apply changes (logout/login or reboot required)
----

=== User-Specific Locale

Override for your user only without affecting system:

[source,bash]
----
# Add to ~/.config/fish/conf.d/50-locale.fish
set -gx LANG en_US.UTF-8
set -gx LC_ALL en_US.UTF-8

# Or for bash users, add to ~/.bashrc
export LANG=en_US.UTF-8
export LC_ALL=en_US.UTF-8
----

=== Temporary Locale Change

For a single session or command:

[source,bash]
----
# Single command with different locale
LANG=en_US.UTF-8 date

# New shell with different locale
LANG=en_US.UTF-8 fish
----

=== Available Locales

[source,bash]
----
# List installed locales
locale -a

# DevBase generates the locale you configure
# Organizations can set their preferred locale in org.env
----

NOTE: Language packs and translated manpages are only installed when a specific locale is configured (typically through organization settings).

== Theme Switching

Use the `devbase-theme` command to switch themes (authoritative list in `libs/theme-registry.sh`):

[source,bash]
----
# Everforest (default)
devbase-theme everforest-dark
devbase-theme everforest-light

# Catppuccin
devbase-theme catppuccin-mocha   # Dark
devbase-theme catppuccin-latte   # Light

# Tokyo Night
devbase-theme tokyonight-night   # Dark
devbase-theme tokyonight-day     # Light

# Gruvbox
devbase-theme gruvbox-dark
devbase-theme gruvbox-light

# Nord
devbase-theme nord

# Dracula
devbase-theme dracula

# Solarized
devbase-theme solarized-dark
devbase-theme solarized-light

# Restart terminal for all changes to take effect
----

The theme setting persists across terminal sessions and affects: bat, delta, btop, k9s, FZF, Neovim, and vifm. File manager lf uses LS_COLORS which is already themed via eza/dircolors.

=== Bundled Themes

**btop themes:**

DevBase bundles the following btop themes in `~/.config/btop/themes/`:

- `everforest-dark-hard.theme` - Everforest dark variant
- `everforest-light-medium.theme` - Everforest light variant
- `catppuccin_mocha.theme` - Catppuccin dark theme
- `catppuccin_latte.theme` - Catppuccin light theme
- `gruvbox_dark.theme` - Gruvbox dark (uses underscore, not dash)
- `gruvbox_light.theme` - Gruvbox light (uses underscore, not dash)
- `tokyo-night.theme` - Tokyo Night dark theme
- `tokyo-storm.theme` - Tokyo Storm (used as fallback for tokyo-day)

NOTE: Tokyo Day theme doesn't exist in btop, so tokyo-storm is used as a fallback. Gruvbox themes use underscores (gruvbox_dark) not dashes in btop.

**k9s skins:**

DevBase bundles the following k9s skins in `~/.config/k9s/skins/`:

- `everforest-dark.yaml` - Everforest dark theme
- `everforest-light.yaml` - Everforest light theme
- `catppuccin-mocha.yaml` - Catppuccin dark theme
- `catppuccin-latte.yaml` - Catppuccin light theme
- `gruvbox-dark.yaml` - Gruvbox dark theme
- `gruvbox-light.yaml` - Gruvbox light theme

When you run `devbase-theme`, the `skin:` setting in `~/.config/k9s/config.yaml` is updated to reference the appropriate skin file.

How k9s finds skins:
1. `$XDG_CONFIG_HOME/k9s/skins/` (usually `~/.config/k9s/skins/`)
2. `$HOME/.config/k9s/skins/`
3. `$HOME/.k9s/skins/`

The skin is referenced by name (without `.yaml` extension) in config.yaml:
[source,yaml]
----
k9s:
  skin: everforest-dark
----

NOTE: Tokyo Night themes are not available for k9s, so fallbacks are used: `tokyonight-night` → `gruvbox-dark`, `tokyonight-day` → `everforest-light`

Theme sources:
- btop: https://github.com/aristocratos/btop/tree/main/themes
- k9s: Community contributed skins

=== WSL Windows Terminal Integration

TIP: DevBase now *automatically updates* Windows Terminal color schemes when you change themes!

When you run `devbase-theme`, it will:

1. Update all CLI application themes (bat, FZF, vifm, Neovim, etc.)
2. Automatically update Windows Terminal color scheme
   - *Dark themes* → "One Half Dark"
   - *Light themes* → "One Half Light"
3. Changes apply immediately (no terminal restart needed)

*Requirements:*

- jq installed (usually included in DevBase)
- Windows Terminal (Microsoft Store version)

*Manual Windows Terminal theme change (if needed):*

1. Open Windows Terminal Settings (Ctrl+,)
2. Navigate to: Your Ubuntu profile → Appearance → Color scheme
3. Select any available scheme

NOTE: For exact color matching beyond built-in schemes, you can create custom color schemes in Settings → Color schemes.

This automatic integration only applies to WSL. On native Ubuntu, terminal emulators (Ghostty, Alacritty, etc.) use their own theming systems.

== Neovim

DevBase installs LazyVim only when selected and `~/.config/nvim` is absent. Existing configurations, including empty directories and symlinks, are preserved. For a LazyVim installation, add custom configurations:

[source,lua]
----
-- Add/override plugins in ~/.config/nvim/lua/plugins/custom.lua
return {
  { "github/copilot.vim" },
}

-- Add custom keymaps to existing ~/.config/nvim/lua/config/keymaps.lua
-- (Edit the file, don't replace it)
vim.keymap.set('n', '<leader>q', ':qa<CR>')

-- Or use standard Neovim after directory
-- ~/.config/nvim/after/plugin/custom.lua
vim.opt.relativenumber = false
----

NOTE: Fresh installation is staged; cloning, the configured pinned checkout and initial configuration must succeed before publication. Explicitly running `devbase-theme` can still update `lua/plugins/colorscheme.lua`.

See link:https://www.lazyvim.org/configuration[LazyVim documentation] for more customization options.

== Starship Prompt

DevBase initializes `~/.config/starship/starship.toml` only when absent. Fish respects an already-set `STARSHIP_CONFIG`; otherwise it prefers `~/.config/starship.toml` if present, then the DevBase-initialized nested path. Edit the active file to customize your prompt:

[source,toml]
----
# Add or modify sections
[directory]
truncation_length = 5
truncate_to_repo = false

[git_status]
disabled = false
----

Changes take effect in new terminal sessions.

== mise Tool Versions

DevBase generates `$XDG_CONFIG_HOME/mise/config.toml` (normally `~/.config/mise/config.toml`) from its package selections. This global file is managed by the installer: direct edits and global selections can be replaced on setup or update. Project configuration files are not rewritten by DevBase.

Project-specific:
[source,bash]
----
cd myproject
mise use node@18
mise use python@3.11
----

Global selections (can be replaced by the next DevBase setup):
[source,bash]
----
mise use -g node@20
mise use -g python@3.12
----

Use `mise current` to check the effective versions. Setup validates the generated TOML and backs up the existing global configuration before replacement; invalid package definitions, invalid TOML and failed writes leave it intact.

NOTE: A custom `MISE_GLOBAL_CONFIG_FILE` may bypass DevBase's generated global config. Review that file and the effective configuration when using this override.

== Zellij Terminal Multiplexer

Enable or disable automatic Zellij startup:

[source,bash]
----
# Create personal config if it doesn't exist
touch ~/.config/fish/conf.d/50-personal.fish

# Enable Zellij autostart (edit the file to add this line)
echo 'set -gx DEVBASE_ZELLIJ_AUTOSTART "true"' >> ~/.config/fish/conf.d/50-personal.fish

# Or disable Zellij autostart
# echo 'set -gx DEVBASE_ZELLIJ_AUTOSTART "false"' >> ~/.config/fish/conf.d/50-personal.fish

# Reload config
exec fish
----

TIP: To avoid duplicates, edit `50-personal.fish` directly instead of appending.

== Editor Preference

Change your default editor after installation:

[source,bash]
----
# Edit ~/.config/fish/conf.d/50-personal.fish and add:

# For Neovim:
set -gx EDITOR nvim
set -gx VISUAL nvim

# For nano:
set -gx EDITOR nano
set -gx VISUAL nano

# Reload config
exec fish
----

== Environment Variables

Add custom environment variables to `~/.config/fish/conf.d/50-env.fish`:

[source,bash]
----
# XDG_RUNTIME_DIR is already set by DevBase
set -gx DOCKER_HOST "unix://$XDG_RUNTIME_DIR/podman/podman.sock"
set -gx JAVA_HOME "/usr/lib/jvm/java-21-openjdk"
set -gx MY_CUSTOM_VAR "value"
----

NOTE: DevBase sets `XDG_RUNTIME_DIR` to `/run/user/(id -u)` automatically.

== Fish Greeting

Customize the Fish shell greeting:

[source,bash]
----
# Add to ~/.config/fish/conf.d/50-personal.fish

# Custom greeting
set -g fish_greeting "Welcome back, $USER!"

# Or disable greeting completely (DevBase default)
set -g fish_greeting ''
----

== Backup Before Reinstall

The managed dotfile bulk copy backs up existing destinations under `$XDG_DATA_HOME/devbase/backup/dot_backup/` (normally `~/.local/share/devbase/backup/dot_backup/`), covering the full copied tree and preserving symlinks as links. A failed backup blocks bulk replacement. Backup rotation happens after preferences are confirmed, when the installation phase begins: `backup/` holds the current run and `backup.old/` the previous run. Archive these directories and your personal configs before repeated installs if you need longer history. Historical `~/.devbase_backup_*` directories are not automatically deleted. This is not a backup of every configuration writer; many personal paths are preserved in place instead.

== Configuration File Locations

DevBase configuration files are located in:

=== Fish Shell
- Main config: `~/.config/fish/config.fish`
- Custom functions: `~/.config/fish/functions/`
- Configuration directory: `~/.config/fish/conf.d/`
  * Shipped filenames, including `10-ulimits.fish`, are managed and updated on reinstall.
  * Personal files with noncolliding names, such as `50-personal.fish`, are preserved.

=== Git
- Global config: `~/.config/git/config` (DevBase managed)
- Personal settings: `~/.gitconfig` (unrelated keys retained; setup writes selected settings)
- Global gitignore: `~/.config/git/.gitignore`
- Allowed signers: `~/.config/ssh/allowed_signers`

=== SSH
- Main config: `~/.ssh/config` (DevBase managed)
- Organization config: `~/.config/ssh/custom.config` (organization provided)
- User config: `~/.config/ssh/user.config` (your personal hosts, preserved)
- Known hosts: `~/.ssh/known_hosts` (create-only seed, then personally maintained)
- Allowed signers: `~/.config/ssh/allowed_signers`

=== Neovim
- Config directory: `~/.config/nvim/`
- Custom plugins: `~/.config/nvim/lua/plugins/`
- Keymaps: `~/.config/nvim/lua/config/keymaps.lua`
- Options: `~/.config/nvim/lua/config/options.lua`
- After directory: `~/.config/nvim/after/` (for personal overrides)

=== Terminal & Shell Tools
- Starship: `$STARSHIP_CONFIG` (normally `~/.config/starship/starship.toml`; conventional `~/.config/starship.toml` takes precedence if present)
- Zellij: `~/.config/zellij/config.kdl`
- btop: `~/.config/btop/btop.conf`
- Delta themes: `~/.config/delta/themes.config`

=== Development Tools
- mise global config: `~/.config/mise/config.toml` (DevBase managed)
- Lazygit: `~/.config/lazygit/config.yml`
- Podman/Containers: `~/.config/containers/registries.conf` (create-only when a registry is configured)

=== User Binaries
- Personal scripts: `~/.local/bin/` (in PATH)

TIP: Check shipped filenames when naming personal Fish configs; no numeric range is reserved against collisions.
