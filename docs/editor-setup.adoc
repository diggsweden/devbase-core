= Editor Setup

== VS Code

=== WSL Users - Important

VS Code extensions on WSL are installed in the *VS Code Server* (`~/.vscode-server`), which is created when you first connect from Windows VS Code using the Remote-WSL extension.

DevBase setup handles this automatically:

1. **During setup**: If Remote-WSL extension is installed, setup offers to automatically launch VS Code to create vscode-server
2. **If you decline or it fails**: Setup provides step-by-step instructions for your specific user
3. **After vscode-server is created**: Re-run setup to install extensions

==== Per-User Setup

Each WSL user (including when using `su -l username`) needs their own vscode-server:

[source,bash]
----
# Connect from WSL as specific user
wsl -d Ubuntu-24.04 -u username
/mnt/c/Program\ Files/Microsoft\ VS\ Code/bin/code .

# Or let DevBase setup handle it automatically during installation
----

The setup script detects your current user and provides tailored instructions.

=== Extensions

Extensions come from `dot/.config/devbase/packages.yaml`. Setup installs them when VS Code is detected and the *VS Code extensions* preference is enabled; otherwise run `devbase-vscode-extensions` afterwards. Core set:
- Asciidoctor
- YAML (Red Hat)
- SonarLint
- SARIF Viewer
- i18n Ally
- Material Icon Theme
- One theme extension per DevBase theme (Everforest, Catppuccin, Tokyo Night, Gruvbox, Nord, Dracula, Solarized)
- Neovim (`asvetliakov.vscode-neovim`, optional, prompted by `devbase-vscode-extensions`)

Selected language packs add their own extensions, for example the Java pack installs the Red Hat Java tooling and the Node pack installs ESLint, Prettier, Tailwind CSS and Volar. Run `devbase-vscode-extensions --list` to see the exact set for your selection.

Settings applied:

- WSL / Remote-WSL: `~/.vscode-server/data/Machine/settings.json`
- Native Linux: `~/.config/Code/User/settings.json`

== Neovim

DevBase installs LazyVim starter configuration with:
- LSP support
- Treesitter syntax
- A colorscheme matching the selected DevBase theme (`lua/plugins/colorscheme.lua`, written by `devbase-theme`)
- Leader key: `space`

Config: `~/.config/nvim/`

Setup preserves the entire existing path, including an empty directory or symlink. A fresh install is staged and published only after the clone, configured pinned checkout and initial configuration succeed; Neovim templates are excluded from the bulk dotfile copy.

`devbase-theme <name>` rewrites `~/.config/nvim/lua/plugins/colorscheme.lua` with the same generator setup uses, but only when that LazyVim plugin directory exists; other Neovim configurations are left alone.

Add personal configs to:
- `~/.config/nvim/lua/plugins/` - Custom plugin configurations
- `~/.config/nvim/after/` - Personal overrides

See link:https://www.lazyvim.org/configuration[LazyVim documentation] for customization options.

== IntelliJ IDEA

Version-specific user VM options at `~/.config/JetBrains/IntelliJIdea<major.minor>/idea64.vmoptions` are initialized only when absent. Existing files, including empty files and symlinks, are preserved; `XDG_CONFIG_HOME` is respected.

Import code styles from devbase-core installation directory:
- Java: `.config/devtools/formatting/java/eclipse-java-google-style.xml`
- Checkstyle: `.config/devtools/linting/java/google_checks.xml`

Settings → Editor → Code Style → Import Scheme

These files are copied to `~/.config/devtools/` during installation.

== Common Issues

=== VS Code can't find tools
Add to settings.json:
[source,json]
----
"terminal.integrated.profiles.linux": {
  "fish": {
    "path": "/usr/bin/fish"
  }
}
----

=== Neovim plugins not loading
[source,bash]
----
rm -rf ~/.local/share/nvim
nvim --headless "+Lazy! sync" +qa
----
